# cube-idp — Back to Basics: Project Structure Design

Date: 2026-07-27
Status: approved (owner-reviewed in session)
Branch: `RafPe/rework-to-basics`

## 1. Context and decision drivers

The previous implementation (~20.4k non-test LOC, 33 internal packages, 45 ADRs)
grew fast and degraded structurally: a 1,504-line `internal/up/up.go` importing
19 internal packages, a `cmd/` layer importing 25 internal packages and doing
business logic, a central diagnostics registry imported by every package
(fan-in 30), and import-cycle workarounds (type aliases, package splits) caused
by factories importing their implementations. The rebuild starts from zero on
this branch.

Owner decisions driving this design (recorded from the 2026-07-27 session):

- **The goal of this rework is v0** — a greenfield baseline holding only the
  config domain. No cluster provider, no engine, no packs yet. From v0,
  components are added progressively in small milestones.
- **Config is KRM-shaped and CRD-ready** — a `Config` kind in api group
  `cube-idp.dev/v1alpha1`, loaded from a local YAML file today, with Go types
  following Kubernetes API conventions so promotion to a served CRD is
  mechanical, not a rewrite.
- **Interface-driven first** — small, mockable interfaces so everything is
  properly testable.
- **All prior user-facing contracts are free to redesign.**
- **Binding coding rules:** `golang-ai-coding-guardrails.md` (owner's guardrails
  document — error handling, context, testing, dependency management, code
  organization).
- Old process machinery (ADR corpus, SDD, board automation) is set aside for
  this rework.

Research provenance: four parallel research streams (old-codebase structural
autopsy; Go structure-pattern evaluation against the guardrails; prior-art
survey of kind, kubeadm, helm v4, flux2, k3d, idpbuilder, kubebuilder; KRM
config machinery deep-dive). Their conclusions converged on the structure
below.

## 2. The chosen structure, in one line

Standard Go layout (`cmd/` + `internal/` + public `api/`) skeleton; one
package per component domain inside `internal/` (DDD-lite topology, no DDD
ceremony); consumer-side interfaces by default with a driver-pattern exception
for swappable backends; error machinery separated from per-domain error
catalogs; a thin phase-runner orchestrator; CI-enforced size limits.

Rejected alternatives (evaluated, not skipped): layered
(handlers/services/repositories — wrong decomposition axis for a CLI, maximal
edit fan-out per feature), textbook hexagonal (port/adapter tax on every
dependency for a benefit only two domains need; guardrails mark it MUST-NOT
for small teams), textbook DDD ceremony (aggregates/repositories — same
MUST-NOT), fully-internal variant with hand-rolled TypeMeta (defeats
mechanical CRD promotion).

### v0 CLI surface

Exactly two subcommands, exercising the whole config pipeline end to end:

- `cube-idp config validate [-f cube.yaml]` — load → default → validate;
  prints aggregated errors with codes; exit 0 (valid) or 2 (config error).
- `cube-idp config show [-f cube.yaml]` — prints the loaded, defaulted config
  back as YAML (proves round-tripping).

No `init`, no `up`, no cluster in v0.

## 4. The Config API

### 4.1 API group decision

**Root group `cube-idp.dev` for the `Config` kind.** A group is an ownership
and versioning boundary, not a labeling scheme: kind (`kind.x-k8s.io`) and
kubeadm (`kubeadm.k8s.io`) use a single root group because the product owns
one config document; Flux uses per-controller groups because each group is a
separate controller owning separate kinds. Our `Config` is a single aggregate
document — its cluster/engine/packs sections are fields of one spec, versioned
and converted together.

**Per-component groups (`<component>.cube-idp.dev`) are reserved for future
kinds a component actually owns** — e.g. a future `Spoke` kind under
`spokes.cube-idp.dev`, or a pack-discoverability CRD under
`packs.cube-idp.dev`. Subgroups are born with the kinds they own, never
applied preemptively to sections of one document.

### 4.2 Types — CRD-style, real apimachinery

```go
// api/config/v1alpha1/config_types.go

// +kubebuilder:object:root=true

// Config is the cube-idp configuration document. KRM-shaped: loaded from
// a file today, promotable to a served CRD later with no type changes.
type Config struct {
    metav1.TypeMeta   `json:",inline"`
    metav1.ObjectMeta `json:"metadata,omitempty"` // only metadata.name is honored

    Spec ConfigSpec `json:"spec,omitempty"`
}

// ConfigSpec is intentionally minimal. Each future domain adds ONE typed
// sub-struct (Cluster, Engine, Packs, ...) plus its own defaults and
// validation — this file grows, the loading machinery never changes.
type ConfigSpec struct{}
```

Conventions:

- Real `metav1.TypeMeta`/`ObjectMeta` (hand-rolled metadata copies defeat
  mechanical CRD promotion — the whole point of "CRD-ready").
- json tags only; optionals get `omitempty`; pointers only where "unset vs
  zero" must differ (else non-pointer + defaulting).
- `metadata.name` is the cube identity (required, name-regex validated). All
  other ObjectMeta fields (uid, resourceVersion, finalizers, …) are
  accepted-and-ignored, documented as such.
- No Status in the file-loaded phase; promotion may add it additively.
- `+kubebuilder:object:root=true` from day one; validation markers added
  opportunistically (inert now, free OpenAPI/CRD schema later).
- deepcopy generated by controller-gen and committed
  (`zz_generated.deepcopy.go`). It is inert until a scheme exists — accepted
  cost, avoids retrofitting markers at promotion time.

Sample document:

```yaml
# examples/cube.yaml
apiVersion: cube-idp.dev/v1alpha1
kind: Config
metadata:
  name: dev
spec: {}
```

### 4.3 Loading pipeline — decode → default → validate

kind-style manual GVK dispatch + strict decode; no `runtime.Scheme` until a
second version or a served CRD needs it (adding one later is registration,
not a type rewrite).

```go
// internal/config/load.go

// Load reads, strictly decodes, defaults, and validates a Config.
// Fail fast: a non-nil *Config is always complete and valid.
func Load(fsys fs.FS, path string) (*v1alpha1.Config, error) {
    raw, err := fs.ReadFile(fsys, path)
    if err != nil {
        return nil, fmt.Errorf("read config %s: %w", path, err)
    }

    var tm struct{ APIVersion, Kind string }              // 1. GVK pre-parse
    if err := yaml.Unmarshal(raw, &tm); err != nil {
        return nil, fmt.Errorf("determine apiVersion/kind: %w", err)
    }

    switch tm.APIVersion + "/" + tm.Kind {
    case v1alpha1.GroupVersion.String() + "/Config":
        var c v1alpha1.Config
        if err := yaml.UnmarshalStrict(raw, &c); err != nil {  // 2. unknown fields REJECTED
            return nil, errUnknownField(err)
        }
        c.Default()                                            // 3. defaults BEFORE validate
        if errs := c.Validate(); len(errs) > 0 {               // 4. ALL problems at once
            return nil, errInvalidConfig(errs.ToAggregate())
        }
        return &c, nil
    default:
        return nil, errUnsupportedAPIVersion(tm.APIVersion + "/" + tm.Kind)
    }
}
```

- Validation uses `k8s.io/apimachinery/pkg/util/validation/field` —
  `field.ErrorList` gives path-qualified errors (`spec.x: Invalid value: …`)
  and aggregates so the user sees every problem in one run.
- Versioning: `v1alpha1` is the only version and the hub. When `v1beta1`
  arrives, it becomes the hub and `v1alpha1` becomes a spoke with manual
  `ConvertTo`/`ConvertFrom` (kubebuilder-style; no conversion-gen, no internal
  hub version — that machinery is only justified at 2+ served versions).

## 5. Error architecture

**Machinery is separated from the catalog.** The old central registry (every
code in one package, imported by all 30 packages) is explicitly not rebuilt.

### 5.1 Machinery — `internal/cubeerr` (leaf, never grows a catalog)

```go
type Code string

// Coded is the only error shape that reaches a user:
// code + summary + remediation, wrapping the technical cause.
type Coded struct {
    Code        Code
    Summary     string
    Remediation string
    err         error
}

func (e *Coded) Error() string { return fmt.Sprintf("%s: %s", e.Code, e.Summary) }
func (e *Coded) Unwrap() error { return e.err }

func Wrap(code Code, summary, remediation string, cause error) *Coded {
    return &Coded{Code: code, Summary: summary, Remediation: remediation, err: cause}
}

// ExitCode maps any error chain to the process exit code.
func ExitCode(err error) int {
    var c *Coded
    switch {
    case err == nil:         return 0
    case errors.As(err, &c): return exitFor(c.Code) // CFG → 2 (config), default 1
    default:                 return 1
    }
}
```

### 5.2 Codes — component mnemonics, declared per-domain

Format: `CUBE-<TAG>-NNN`. The tag is the namespace: no numeric range
allocation, no exhaustion, no collisions by construction; the code itself
tells the user (and grep) which component failed. Each domain owns its `NNN`
sequence in its own `errors.go`.

```go
// internal/config/errors.go — the config domain owns CUBE-CFG-*

const (
    CodeUnsupportedAPIVersion cubeerr.Code = "CUBE-CFG-001"
    CodeUnknownField          cubeerr.Code = "CUBE-CFG-002"
    CodeInvalidConfig         cubeerr.Code = "CUBE-CFG-003"
)

func errUnsupportedAPIVersion(got string) error {
    return cubeerr.Wrap(CodeUnsupportedAPIVersion,
        fmt.Sprintf("unsupported apiVersion/kind %q", got),
        `set apiVersion: cube-idp.dev/v1alpha1 and kind: Config`, nil)
}
```

Component tag registry (human-readable; lives here, not in code):

| Tag | Component | Package | Arrives |
|---|---|---|---|
| `CFG` | config (api types + loader) | `internal/config` | v0 |
| `CLI` | cli / output | `internal/cli` | v0 |
| `CLU` | cluster provider | `internal/cluster` | later |
| `KUB` | kube client access | `internal/kube` | later |
| `ENG` | gitops engine | `internal/engine` | later |
| `PKG` | packs (fetch/render/deps) | `internal/pack` | later |
| `REG` | registry / OCI artifacts | `internal/registry` | later |
| `APP` | apply / SSA / inventory | `internal/apply` | later |
| `TLS` | trust / certificates / CA | `internal/trust` | later |
| `SPK` | spokes | `internal/spoke` | later |
| `ORC` | orchestrator (phases) | `internal/orchestrator` | later |

New components add a row and pick an unused tag; nothing renumbers.

### 5.3 Rules

- Sentinel/wrapped errors (`%w` + context on every hop, guardrails §1) below
  the CLI boundary; `*cubeerr.Coded` for anything that reaches the user.
- Only `internal/cli/exit.go` renders errors (stderr) and maps exit codes.
  Domains never print.
- User-facing rendering:

```
$ cube-idp config validate -f cube.yaml
✗ CUBE-CFG-003: invalid config
    metadata.name: Required value: cube identity is required
  → fix the fields above and re-run `cube-idp config validate`
$ echo $?
2
```

## 6. Interface doctrine

Two kinds of seams, with a bright line between them:

**Kind A — consumer-side seams (the default).** The consuming package defines
the interface it needs, 1–3 methods (guardrails §6); domains return concrete
structs ("accept interfaces, return structs"). Mocks are hand-rolled
function-field structs per the guardrails template — no mockgen, no generated
mocks.

```go
// defined WHERE IT'S USED (e.g. the future orchestrator):
type packApplier interface {
    Apply(ctx context.Context, objs []*unstructured.Unstructured) error
}

type mockApplier struct {
    ApplyFunc func(ctx context.Context, objs []*unstructured.Unstructured) error
}
func (m *mockApplier) Apply(ctx context.Context, o []*unstructured.Unstructured) error {
    if m.ApplyFunc != nil { return m.ApplyFunc(ctx, o) }
    return fmt.Errorf("mockApplier.Apply not implemented")
}
```

**Kind B — driver seams (the exception, only for genuinely swappable
backends: cluster providers, gitops engines).** The interface and its
behavioral conformance suite live in the domain package, next to what they
define — the `database/sql/driver` pattern. Implementations live in
subpackages and each runs the shared suite.

```go
// internal/engine/engine.go
type Engine interface {
    Deliver(ctx context.Context, r *pack.Rendered, src ArtifactRef) ([]*unstructured.Unstructured, error)
    Health(ctx context.Context) ([]ComponentHealth, error)
}

// internal/engine/conformance.go
func RunEngineConformance(t *testing.T, newEngine func() Engine) { /* shared assertions */ }

// internal/engine/flux/flux_test.go
func TestConformance(t *testing.T) {
    engine.RunEngineConformance(t, func() engine.Engine { return flux.New(/*…*/) })
}
```

Driver-seam design rules carried from the old codebase's proven `Engine` seam:
interfaces are **pure** where possible (return objects; the caller applies —
this is what made conformance testable against envtest instead of live
clusters), optional capabilities are separate small interfaces
(`ImageLoader`-style) type-asserted by the consumer, and seams are narrowed
over time, never widened casually.

**v0 has zero hand-rolled interfaces, deliberately.** The loader's only
outside-world dependency is reading a file: it takes stdlib `io/fs.FS`,
mocked with `testing/fstest.MapFS`. Interface-driven does not mean inventing
interfaces before a second consumer or implementation exists.

## 7. Orchestration — the god-file guard

When `up` arrives it is a kubeadm-style phase runner, not a function:

```go
// internal/orchestrator/runner.go
type Phase struct {
    Name string          // enables: cube-idp up --skip-phases=install-engine
    Run  func(ctx context.Context, s *State) error
}

func RunPhases(ctx context.Context, phases []Phase, s *State) error {
    for _, p := range phases {
        if err := p.Run(ctx, s); err != nil {
            return fmt.Errorf("phase %s: %w", p.Name, err)
        }
    }
    return nil
}

// internal/orchestrator/up.go — the whole up flow, forever:
func UpPhases(deps Deps) []Phase {
    return []Phase{
        {Name: "ensure-cluster", Run: deps.EnsureCluster},
        {Name: "install-engine", Run: deps.InstallEngine},
        {Name: "deliver-packs",  Run: deps.DeliverPacks},
        {Name: "verify-health",  Run: deps.VerifyHealth},
    }
}
```

Three structural rules make the 1,500-line `up.go` unrepresentable:

1. The orchestrator depends **only on interfaces** (Kind-A seams) injected via
   a deps struct — it sequences, it never decides. Business logic lives in the
   domain packages.
2. **Leaf domains stay leaf** (api types, `cubeerr`, future `kube`).
   Factories and composition live at the orchestrator/CLI edge, never inside
   domain packages — every old import-cycle workaround traced to a factory
   importing its implementations.
3. **Size limits are CI-enforced, not aspirational**: function <50 lines via
   golangci-lint `funlen`; file <300 lines via a small check in `make lint`
   (golangci-lint has no file-length linter) — both part of the green
   definition from commit one (guardrails §7). Agents don't self-limit; the
   gate does.

## 8. Growth path

Every future component is one new `internal/<domain>` package plus one typed
sub-struct in `ConfigSpec`. Wiring touches exactly two places: a constructor
call and one phase registration. Existing packages are not edited.

```
cube-idp/                                # future full state
├── cmd/cube-idp/main.go                 # unchanged
├── api/config/v1alpha1/                 # ConfigSpec gains Cluster, Engine, Packs sub-structs
├── internal/
│   ├── cli/                             # + up.go, down.go, status.go — still flag-mapping only
│   ├── orchestrator/                    # thin sequencer, interfaces only
│   ├── config/                          # unchanged            CUBE-CFG-*
│   ├── cluster/  (+ kind/)              # driver seam           CUBE-CLU-*
│   ├── engine/   (+ flux/)              # driver seam           CUBE-ENG-*
│   ├── pack/                            #                       CUBE-PKG-*
│   ├── kube/                            # leaf                  CUBE-KUB-*
│   ├── apply/                           #                       CUBE-APP-*
│   └── cubeerr/                         # unchanged forever
```

Build sequence (from the old-codebase autopsy, ordered by dependency):
config → kube → apply → cluster → pack → engine → registry → orchestrator
(`up`) → periphery (trust, spokes, lock, doctor, diff, …).

## 9. Testing strategy

- Table-driven tests for every exported function (guardrails §4); error paths
  are first-class cases, not afterthoughts.
- v0: loader tested over `fstest.MapFS` fixtures (valid, unknown field, wrong
  apiVersion, missing name, empty file); defaults and validation tested as
  pure functions; golden-file test for `config show` output.
- Assertions on errors go through `errors.As(*cubeerr.Coded)` + code equality,
  never string matching.
- Driver seams ship exported `Run<Seam>Conformance(t, factory)` suites,
  designed to run without live infrastructure wherever possible.
- Verification is always real commands: `go build ./... && go vet ./... &&
  go test ./... -count=1` plus `golangci-lint run`.

## 10. Tooling and dependencies

Makefile targets: `build`, `test`, `generate` (controller-gen deepcopy),
`lint`. controller-gen is pinned as a Go tool dependency (build-time only,
never a runtime import).

Runtime dependencies in v0 — the complete list:

| Module | Why |
|---|---|
| `k8s.io/apimachinery` | metav1 types, `runtime.Object`, `util/validation/field` — it *is* the KRM convention |
| `sigs.k8s.io/yaml` | `UnmarshalStrict` (YAML→JSON path honoring json tags) |
| `github.com/spf13/cobra` | CLI framework (K8s ecosystem norm) |

Build-only: `sigs.k8s.io/controller-tools` (controller-gen). Everything else
is stdlib. The old dependency tree (helm SDK, controller-runtime, TUI stack,
forked go-getter, transitive cloud SDKs) is not inherited; each future heavy
dependency must be re-justified by the component that needs it.

## 12. Decisions log (all owner-approved 2026-07-27)

1. Approach A: standard skeleton + domain packages + public `api/`.
2. `k8s.io/apimachinery` adopted; Config is CRD-style
   (TypeMeta/ObjectMeta/Spec), controller-gen deepcopy from day one.
3. Driver-pattern seams (interface + conformance in the domain package) for
   engine and cluster; consumer-side interfaces everywhere else.
4. CI-enforced size limits (file <300, function <50) in the green gate.
5. Error codes are component mnemonics `CUBE-<TAG>-NNN`; machinery
   (`cubeerr`) separated from per-domain catalogs; tag registry in this doc.
6. API group is root `cube-idp.dev` for `Config`; per-component subgroups
   reserved for future kinds a component owns.
7. v0 CLI surface: `config validate` and `config show` only.
8. `ConfigSpec` starts empty; each component adds one typed sub-struct.
